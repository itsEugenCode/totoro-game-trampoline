# ТЗ на рисунки

Задание для генерации картинок. Код рисунки не создаёт и ждёт файлы в `unity/Assets/Art/`.

Общий блок ниже вставляется в начало каждого запроса.

```text
Уютная 2D-игра, вид строго сбоку. Персонажи чуть пиксельные, мягкие формы, пастель, сказочный лес. Фон, если он есть, нарисованный, не фото и не 3D. Без текста, без рамки, без интерфейса, без водяных знаков, без реалистичного меха и без копии кадра из фильма. Один объект на картинке, фон прозрачный, если ниже не сказано иначе. Объект смотрит вправо.
```

## Правила файлов

- Формат PNG.
- У персонажей, Тоторо, земли и предметов фон прозрачный. У лесного задника фон сплошной: это картина.
- Края ровные, без размытой каймы и без полупрозрачной грязи по контуру.
- Мэй — единица масштаба: ровно 128 пикселей в высоту. Остальные размеры считаются от неё.
- Точка опоры у тех, кто стоит или лежит, — низ по центру. У летающих предметов — центр картинки.
- В кадре только сам объект. Нет тени на отдельной плоскости, нет земли под персонажем, нет второго существа, если это не сказано в карточке.

Сначала нужны четыре файла: без них сцена не собирается. Остальные можно принести следом.

## Не входит в эту партию

## Сборка персонажей в Unity

Карточки первой партии выше остаются как есть. Этот раздел задаёт те же три файла так, чтобы спрайт, импорт и коллайдер собирались без подбора на глаз.

Общая шкала: Мэй — 1 мировая единица роста. У всех трёх персонажей одни и те же настройки импорта, иначе рост разъедется.

| Поле импорта | Значение |
| --- | --- |
| Путь | `unity/Assets/Art/` |
| Texture Type | Sprite (2D and UI) |
| Sprite Mode | Single |
| Pixels Per Unit | 128 |
| Mesh Type | Full Rect |
| Extrude Edges | 0 |
| Filter Mode | Point |
| Compression | None |
| Mip Maps | выключены |
| Wrap Mode | Clamp |
| Alpha Is Transparency | включено |

Высота в мире = высота файла в пикселях ÷ 128. Ширина в мире = ширина файла ÷ 128. Проверка в инспекторе спрайта: Bounds у Мэй ровно (1, 1), у Сацуки (1.25, 1.25), у Тоторо (6, 3).

Оси рисунка: x вправо, y вверх, ноль в левом нижнем пикселе. Так же устроен спрайт в Unity. Верхний ряд пикселей файла — это y = высота − 1. Нижний непрозрачный пиксель лежит на y = 0, верхний непрозрачный — на последнем ряду, иначе визуальный рост будет меньше файла.

Запись `a–b` в таблицах долей — это пиксели от `a` включительно до `b` не включая. Соседние участки стыкуются в точке `b`. Прямоугольники частей заданы иначе: левый нижний угол и размер `ширина×высота`, как `Rect` в Unity.

Pivot у всех трёх — низ по центру, доли (0.5, 0). Ступни или контакт с землёй сидят в нуле объекта.

Контур 2 пикселя, цвет `#3C2F2A`, лежит внутри указанных прямоугольников и наружу размер не увеличивает. Заливка — плоские цвета без градиента, без блика и без текстуры меха. Края ступенчатые, без сглаживания. Формы свои: то же настроение большого лесного зверя и двух сестёр, без меток и костюмов из кадра фильма.

Мэй и Сацуки нарисованы лицом вправо. Отдельный файл лицом влево не нужен: поворот влево — это отрицательный `localScale.x` того же спрайта. Тоторо в сцене стоит как нарисован, с `localScale.x = 1`. В запросе на его файл фразу общего блока «смотрит вправо» заменить на «морда влево, глаза закрыты».

Сейчас в коде нет Animator и нет смены кадра. `PlayerMovement` пускает луч земли из позиции объекта вниз. Поэтому ноль объекта стоит на ступнях, а капсула смещена вверх на половину своего роста и в землю не уходит.

Заглушка сцены — другой файл, `unity/Assets/Art/Player.png`: 16×16, Pixels Per Unit 16, pivot (0.5, 0.5), капсула size (0.6, 1), offset (0, 0). Её рост в мире тоже 1. На `Mei.png` эти настройки импорта не переносятся: при PPU 16 Мэй стала бы ростом 8. Размер капсулы (0.6, 1) при замене спрайта сохраняется, меняются pivot и offset.

### Тоторо

- Файл: `unity/Assets/Art/TotoroSleep.png`
- Кадр: 768×384. В карточке первой партии сказано «около 768×384»; для сборки размер ровно этот, чтобы мир делился на 128 без остатка
- Pixels Per Unit: 128
- Размер в мире: 6 × 3
- Pivot: (0.5, 0) — середина нижнего края, на сером контакте с землёй

Лежит, брюхо обращено вверх. Сейчас нужен один этот кадр. Бег, прыжок и падение ему не задаются. Чих и переворот остаются отдельным заданием: каждый такой кадр — свой PNG, и прямоугольник живота для него снимается заново.

Доли кадра, не доли стоящего роста. y от нижнего края:

| Уши на голове | 110–190 | 270–340 | 0.14–0.25 | 0.70–0.89 |
| Усы, несколько прямых линий влево | 0–90 | 120–200 | 0–0.12 | 0.31–0.52 |
| Серый низ, контакт с землёй | 160–740 | 0–64 | 0.21–0.96 | 0–0.17 |
| Серый бок | 200–720 | 64–192 | 0.26–0.94 | 0.17–0.50 |
| Живот | 256, ширина 384 | 192, высота 192 | 0.333–0.833 | 0.50–1.00 |
| Передняя лапа | 200–340 | 0–88 | 0.26–0.44 | 0–0.23 |

Голова по высоте кадра занимает 252 пикселя из 384 (доля 0.66) и остаётся левее x = 256. Лапы — нижние 0.23 высоты. Передние лапы здесь и есть «руки»: они ниже y = 192 и в прямоугольник живота не входят.

Порядок заливки: серый низ и серый бок, поверх них живот, голова, усы, лапы и хвост. Лапы лежат на сером низе, общего пикселя с животом у них нет.

Живот — кремовый прямоугольник с прямыми сторонами и прямыми углами, без округления: так край совпадает с коробкой. Верхний ряд файла, y = 383, закрашен только на x = 256–639. Это ровная линия батута. Уши заканчиваются на y = 340 и до этой линии не достают. Голова ниже плато.

| Закрытый глаз, короткая дуга | `#3A3330` |

На животе нет полос, стрелок и второго рисунка. Нос — простой овал. Уши маленькие, каждое меньше трети головы.

Серый низ закрашен в том числе в точке x = 384, y = 0, чтобы pivot (0.5, 0) лежал на теле, а не в прозрачной дырке между лапами.

Bounce-коллайдер совпадает только с животом. Голова (x до 220), уши, усы, серый бок (y до 192), обе лапы и хвост снаружи этой коробки.

Прямоугольник живота в долях кадра, ноль в левом нижнем углу: x от 1/3 до 5/6, y от 1/2 до 1. В пикселях: x = 256, ширина 384, y = 192, высота 192.

При pivot (0.5, 0) и PPU 128 это `BoxCollider2D`:

- size: (3, 1.5)
- offset: (0.5, 2.25)

Проверка: центр прямоугольника в пикселях от левого нижнего угла — (448, 288). В мире от левого нижнего угла это (3.5, 2.25). Ноль объекта смещён на половину ширины кадра, то есть на 3, поэтому offset.x = 3.5 − 3 = 0.5, offset.y = 2.25. Верх коробки на y = 3 мира и совпадает с верхним краем спрайта. Низ коробки на y = 1.5. Левый край коробки на 2 мира от левого края спрайта, правый на 5: голова левее, задняя лапа правее.

Верх живота остаётся на высоте 3. Текущий прыжок в `PlayerJump` (`jumpSpeed` 10 при `gravityScale` 3) поднимает ступни примерно на 1.7. Файл из‑за этого не уменьшать: высота 384 px и коробка (3, 1.5) зафиксированы.

Отдельный твёрдый коллайдер на серый бок и лапы этот раздел не задаёт. Если он появится позже, он не заменяет коробку живота и не накрывает голову и лапы.
