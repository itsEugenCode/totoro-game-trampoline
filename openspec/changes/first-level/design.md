# Design

## Context

Unity 6000.6.5f1. Активных change нет; в основных спеках: `core-movement`, `totoro-bounce`, `collectibles`, `vertical-camera`. См. `proposal.md`, раздел Why.

Факт по проекту (проверено):

- Одна playable-сцена: `unity/Assets/Scenes/Clearing.unity` (единственная в `EditorBuildSettings`).
- Корни сцены: `Ground` (ширина 24, центр x=0), `Player` Prefab в (0, 0), `Totoro` в (3.5, 0) с `TotoroBounce.upwardSpeed = 24`, пять экземпляров `Collectible` над дугой отскока, `CollectibleTally`, `Main Camera` (orthographic size 6, `useBounds = 0`).
- Prefabs: `Player.prefab`, `Collectible.prefab`. Отдельного Prefab Тоторо нет — объект сцены со спрайтом `TotoroSleep` и trigger живота (size 3×1.5, offset 0.5 / 2.25).
- Игрок (Prefab): `maxSpeed` / `airMaxSpeed` = 4, `jumpSpeed` = 9.5, `gravityScale` = 3, `PlayerVerticalImpulse`, `CollectibleCollector`.
- Опора только по слою `Ground` (луч в `PlayerMovement`).
- Системы respawn / kill zone / checkpoint / finish **нет**.
- Камера уже умеет `useBounds` + `boundsMin` / `boundsMax` без отдельного менеджера.

Оценка досягаемости при текущих числах (g ≈ 9.81 × 3):

| Действие | Прирост высоты от точки запуска | Ориентир world Y |
| --- | --- | --- |
| Прыжок с земли | ≈ 1.5 | пик ≈ 2.0 при старте y≈0.5 |
| Отскок от живота | ≈ 9.8 | пик ≈ 11–12 при запуске с y≈2 |
| Горизонт за полный цикл отскока при `airMaxSpeed` 4 | ≈ 6.5 ед. | руление обязательно для дальних опор |

Геометрия уровня MUST укладываться в эти пределы с запасом; подкрутка импульса/скоростей «под уровень» в этом change запрещена.

## Goals / Non-Goals

**Goals:**

- Короткий понятный маршрут: старт → подход к Тоторо → отскок → промежуточные опоры → финиш.
- Стартовая безопасная площадка и несколько безопасных мест приземления.
- Collectibles, для которых нужно рулить в воздухе после отскока (и/или короткого прыжка).
- Границы камеры по территории уровня.
- Простой возврат после падения за пределы области.
- Проходимость на текущих параметрах Prefab/сцены.
- Повторное использование существующих Prefab и компонентов.

**Non-Goals:**

- Новые механики движения, вторая героиня, инвентарь, задания, магазин, save, прогрессия, сложный UI, сюжетные сцены.
- Перепись `PlayerMovement`, `PlayerJump`, `PlayerVerticalImpulse`, `TotoroBounce`, collectibles, логики `CameraController` (кроме включения/настройки уже существующих полей границ в Inspector).
- Сторонние пакеты, случайная генерация, полноценный арт-пасс.
- Отдельная песочница параллельно первому уровню в этом change.

## Decisions

### Сцена

- Перестраиваем **`Clearing.unity`**, а не заводим вторую playable-сцену: вся текущая интеграция уже здесь, в билде одна сцена. Имя файла можно оставить; содержимое становится первым уровнем.
- `ClearingSceneSetup.cs` не является источником правды для финальной геометрии маршрута (он создаёт плоскую песочницу). Уровень собирается в сцене вручную / точечным editor-хелпером при необходимости; полный rewrite setup-скрипта не обязателен.

### Размеры и границы уровня

Черновая рамка (уточняется в Play, но порядок величин фиксирован дизайном):

| Параметр | Значение |
| --- | --- |
| Горизонт игровой полосы | примерно x ∈ [−8, 20] |
| Пол / «земля» старта | y ≈ 0 (верх опоры) |
| Потолок полезной игры | y ≈ 12 (пик отскока) |
| Зона падения (kill) | сплошной trigger ниже y ≈ −3…−4 на всю ширину + небольшие боковые карманы |
| Границы камеры (`useBounds = true`) | центр камеры в пределах полосы уровня; низ не пускает в пустоту под полом; верх не режет пик отскока (max Y ≥ ~14–16 при size 6) |

Широкая монолитная `Ground` 24 ед. из песочницы **разбивается / дополняется**: стартовый сегмент + подходы + промежуточные платформы. Пустоты между опорами — осознанные пропасти, чтобы работал fall-return.

### Маршрут и объекты

Слева направо (координаты — целевые ориентиры, не жёсткий контракт до Play-подгонки ±1 ед.):

1. **StartPad** — широкая безопасная площадка, слой `Ground`. Спавн игрока на ней (примерно x=−6…−4, y=0). Рядом объект **PlayerSpawn** (пустой Transform) для respawn.
2. **ApproachGround** — короткая опора или продолжение старта до зоны Тоторо, чтобы добежать и коротко прыгнуть в живот без обязательного пропасти сразу.
3. **Totoro** — существующий объект с `TotoroBounce` (~x=3…5, y=0). Основной вертикальный двигатель маршрута. Не дублировать второй bounce; не трогать скрипт, только позицию/при необходимости визуал.
4. **PlatformMidLow** — опора после первого отскока, y≈4.0–5.0, x≈8–10. Доступна с air control после bounce; **не** должна требоваться только с земли прыжком со старта.
5. **PlatformMidHigh** — выше/дальше, y≈6.0–7.5, x≈12–14. Второй шаг маршрута; при необходимости короткий прыжок с MidLow или повторный bounce + руление.
6. **RestLedge** — безопасная полка y≈3.5–4.5, x≈15–17 для восстановления контроля перед финишем (шире узких «пальцев»).
7. **FinishPad** — конечная опора x≈18–20 с **FinishZone** (trigger). Успех = вход игрока в зону; в Play видно флаг на компоненте и/или `Debug.Log`. Нет экрана победы, нет save.

Опционально 1–2 **SafeCheckpoint** (trigger на широких опорах после Тоторо): обновляют точку возврата. Если чекпоинты усложняют проверку — достаточно возврата на **PlayerSpawn**; тогда RestLedge всё равно остаётся как игровая безопасная зона приземления.

### Collectibles

Повторно `Collectible.prefab` + существующий `CollectibleTally`. Текущую кучную дугу из пяти предметов над животом **переразложить** под маршрут (4–5 штук):

| ID | Роль | Ориентир |
| --- | --- | --- |
| C1 | Разогрев у подхода / низкая дуга | достижим коротким прыжком или ранним отскоком |
| C2 | Траектория вправо после bounce | x правее Тоторо, y≈7–9 — нужен air steer |
| C3 | Над/к MidLow | стимулирует приземление на первую высокую опору |
| C4 | К MidHigh или в воздухе между MidLow и MidHigh | требует второй коррекции траектории |
| C5 (опц.) | Рядом с RestLedge / перед финишем | не обязателен для «дойти», но читается как награда маршрута |

Сбор **не** блокирует финиш: условие успеха — зона финиша. Счётчик сессии остаётся инструментом проверки collectibles.

### Траектории (задумка)

1. Старт → бег к Тоторо → короткий hop в живот → импульс 24.
2. В полёте держать вправо (`airMaxSpeed` 4) → забрать C2/C3 → приземление на MidLow.
3. С MidLow: либо короткий прыжок на MidHigh (если Δy и Δx в пределах ~1.5 высоты / короткого разбега), либо спуск к животу и повторный bounce с более ранним/поздним рулением.
4. MidHigh → RestLedge → FinishPad.
5. Промах мимо опоры → падение в kill-зону → возврат на spawn (или последний checkpoint) с обнулением скорости; собранные предметы сессии **не** сбрасываются (обычный жизненный цикл collectibles).

### Падение и возврат

Новые тонкие компоненты уровня (имена рабочие):

- **`FallRespawnZone`** (или эквивалент): большой trigger ниже/по краям; на Enter у объекта с игроком переносит Transform на точку возрождения, обнуляет `Rigidbody2D.linearVelocity`, не вызывает загрузку сцены.
- **`PlayerSpawn` / `RespawnPoint`**: Transform старта; опционально обновляется чекпоинтом.
- Игрок находится по маркеру, который уже есть на Prefab (`CollectibleCollector` / тег / компонент), **без** правок `PlayerMovement` / bounce. Допустим маленький маркер `PlayerRespawnTarget` на Prefab, если иначе нельзя надёжно найти тело — он не меняет физику.

Перезагрузка всей сцены как единственный способ «встать» после падения — отвергается: это слишком грубо для проверки цикла и сбрасывает collectibles.

### Камера

- Включить `useBounds` на `Main Camera`.
- Подобрать min/max под полосу уровня так, чтобы на старте, на пике bounce и на финише кадр не показывал бесконечную пустоту и не отрезал персонажа на верхней дуге.
- Логику `CameraController` не переписывать.

### Визуал

- Платформы: временные спрайты (`Ground.png` / белый квадрат), цветное отличие старта/финиша допустимо.
- Тоторо и collectibles — существующий арт.
- Параллакс `ForestBack` / `ForestFront` не обязателен в этом change.

### Повторное использование

| Существует | Роль на уровне |
| --- | --- |
| `Player.prefab` | персонаж, движение, импульс, collector |
| `Collectible.prefab` | предметы на маршруте |
| `Totoro` + `TotoroBounce` | батут |
| `CollectibleTally` | счёт сессии |
| `CameraController` | follow + bounds |
| слой `Ground` | все твёрдые опоры |

Не создавать заново: системы бега, прыжка, воздуха, bounce, сбора, вертикального follow.

## Risks / Trade-offs

- [Платформа выше досягаемости] → сверка Δy/Δx с таблицей выше в Play; двигать геометрию, не числа импульса.
- [Узкие опоры + airMaxSpeed 4] → делать полки шире «пальца», RestLedge шире средних.
- [Границы камеры режут пик] → поднять `boundsMax.y` / не зажимать верх слишком низко.
- [Respawn через ReloadScene] → отвергнуть; только телепорт + сброс скорости.
- [Дублирование песочницы и уровня] → одна сцена `Clearing`, содержимое = первый маршрут.
- [Финиш как скрытый GameManager] → только зона + флаг/лог, без загрузки сцен и save.
- [Чекпоинты раздувают объём] → MVP: возврат на старт; чекпоинт — если падения с середины маршрута слишком раздражают в Play.

## Migration Plan

Откат — вернуть плоскую `Clearing` (земля 24, Тоторо, дуга collectibles, `useBounds` off), удалить новые level-скрипты и объекты spawn/finish/fall. Prefab игрока и collectible, скрипты движения/bounce/камеры остаются.
